## 3. 待處理

| 1 | **F10b 櫃位 / 冷凍庫主檔維護沒做** | 中 | 產品方案 §4 列為「建議」、§6 又寫「排數 × 層數實際可在主檔改」，但目前沒有對應的 API（`src/routes/` 只有 inbound / outbound / products / slots / movements / state / undo），倉庫與櫃位只能靠 `db/schema.sql` 改。技術方案 §10「不做的事」也沒把它列進去，等於是漏掉而不是刻意不做。**報告前要決定**：補做、或是明講它屬於未來擴充 |
| 2 | 拖曳手勢未用實體滑鼠驗證 | 低 | F5 移位／互換與 F11 丟棄是 HTML5 原生拖曳（`draggable` + `dragstart` / `drop`），自動化工具送的合成滑鼠事件觸發不了，所以改成呼叫頁面自己的 `transfer()` / `discard()`——**和放開滑鼠後跑的是同一段程式**，資料結果已確認正確。但「拖得動、放得準」這件事建議由人用滑鼠或平板再實際拖一次 |
