# 05 效率評估 — 新系統 vs 大黑板（簡報「使用者的抗拒」）

狀態：**草稿，待小組確認；§4 的實測數字要試用一週後填**
依據：老師的「竹南冷凍倉儲公司 驗收與維護」簡報第 5 頁
相關：`docs/04-系統維護.md`（改善項目的實作）、`GET /api/stats`（系統自動量的數字）

> 李太太的問題：「進貨跟出貨，您的系統跟以前的大黑板系統，效率是否有差距？請評估是否可以改進，讓他們的操作可以更簡便、更正確。」

---

## 1. 結論先講

1. **找貨、先進先出、對帳，系統大勝。** 大黑板只記「哪一格有什麼」，不記「哪一批比較舊」；「甘藍菜找不到、幾個月後壓成果菜汁」正是這個缺口。系統直接指出最舊那批在哪一格，並排好走路順序。
2. **「記錄」這一步，1.0 版確實比大黑板慢，也比較容易漏。** 這就是員工抱怨的來源。大黑板的記錄**附著在搬貨動作上**：拿牌子進去、出來順手掛回去，不用另外想。1.0 系統要員工搬完回到電腦前再按一次確認 —— 多一個步驟、而且是在「最忙的時候」，所以才會忘（簡報 NO1）。
3. **2.0 的改善方向：讓記錄重新附著在動作上，並且忘了也會被發現。** 單子帶在身上（手機／平板），每一站拿好就打勾，最後一站打完勾順手回報；沒回報的單一直掛在每一頁最上面，超過 30 分鐘變紅；每天盤點把漏掉的抓回來。

## 2. 流程拆解比較

「步驟」是員工實際要做的動作；「記錄負擔」是除了搬貨以外、為了讓帳正確而多做的事。

### 2.1 進貨

| | 大黑板 | 系統 1.0 | 系統 2.0 |
|---|---|---|---|
| 找空位 | 看黑板上哪些格沒掛牌子 | 系統預填一個空格，可改 | 同左，另外會跳過別張放貨單預定的格子 |
| 到期日 | 不記（憑記憶） | 自動算 = 今天 + 保存天數，可改 | 同左 |
| 搬進去 | 拿那格的牌子 → 放貨 | 看螢幕上的放貨路線 → 放貨 | 手機上逐站看路線 → 放貨 |
| 記錄 | 出來把牌子掛回黑板（**順手，零額外步驟**） | 放貨**之前**就已經按確認入庫 → 放錯格、還沒放，系統都不知道 | 每放好一格打勾；全部打勾後回報才入庫；放到別格就在該站選實際的格子 |
| 記錯／漏記時 | 發現不了 | 發現不了 | 回報前系統是「預定」不是「有貨」；沒回報的單每頁提醒 |
| 多品項 | 一項一項來 | 一張單多項，路線一次排好 | 同左 |

### 2.2 出貨

| | 大黑板 | 系統 1.0 | 系統 2.0 |
|---|---|---|---|
| 找貨 | 看黑板找「甘藍菜」的格子；**不知道哪批最舊** | 系統用先進先出指出去哪幾格、各拿幾籠，排好走路順序 | 同左；已經開在別張單的貨不會重複分配 |
| 搬出來 | 拿牌子進去 → 搬貨 | 照揀貨單搬 | 照手機上的揀貨單搬，每站拿好就打勾 |
| 記錄 | 出來把牌子掛回去（順手） | **要回電腦按「確認出庫」→ 忙著出貨就忘了**（NO1） | 最後一站打勾後，按鈕就在拇指下面；忘了按 → 每頁提醒、30 分鐘變紅 |
| 缺貨 | 進去才發現 | 產生揀貨單時就列出「差幾籠」，讓李太太先決定要不要接單 | 同左 |

### 2.3 操作次數（系統 2.0，一品項、一站）

| 動作 | 進貨 | 出貨 |
|---|---|---|
| 切到入／出庫、選入庫或出庫 | 1～2 | 1～2 |
| 選品項（色塊圖庫，不用下拉找） | 1 | 1 |
| 改籠數 | 1 | 1 |
| 選格子 | 0（已預填） | 0（系統決定） |
| 產生揀貨單預覽 | — | 1 |
| 發單 | 1 | 1 |
| 每站打勾 | 1 | 1 |
| 回報 | 1 | 1 |
| **合計** | **約 6～7 下** | **約 7～8 下** |

多品項時，每多一項只多「選品項、改籠數、打勾」3 下左右。大黑板在這一步幾乎是 0 下，這是誠實的差距；2.0 把這些操作放到員工本來就要看的揀貨單上，並用大按鈕（戴手套也按得到），盡量把差距縮小。

## 3. 已經做的改善（對應 1.0 → 2.0）

| 員工的痛點 | 改善 | 在哪裡 |
|---|---|---|
| 搬完忘了告訴系統 | 發單 → 逐站打勾 → 回報；單子存在資料庫，關掉頁面、換一台平板都看得到 | 入／出庫頁「待回報的單」 |
| 忘了也沒人知道 | 每一頁最上面的提醒列；超過 30 分鐘變紅 | 提醒列 |
| 放到別格帳就亂了 | 回報時可以改成實際放的格子，紀錄寫「原定 X，實際放 Y」 | 放貨單每一站的下拉選單 |
| 兩個人搶同一批貨／同一格 | 發單就保留：別張單拿不到、不能移位、不能佔用 | 後端檢查＋地圖標示 |
| 盤點太麻煩 | 一次盤一整座庫、照走路順序列出，只要改「不一樣」和「壞掉」的，＋－ 按鈕調數字 | 盤點頁 |
| 壞了一箱只能整格丟 | 可以只丟幾籠並選原因 | 地圖格子 → 改籠數／到期日／報廢 |
| 手機、平板沒有右鍵 | 點格子的面板上直接有按鈕 | 倉庫地圖 |
| 別台平板的變化看不到 | 每分鐘自動更新 | 全部頁面 |

## 4. 怎麼量（試用一週後填）

系統自己會量，紀錄頁下方「最近 7 天作業統計」＝ `GET /api/stats?days=7`：

| 指標 | 意思 | 目標 | 實測 |
|---|---|---|---|
| 揀貨：發單到回報（中位數） | 員工跑一趟出貨的時間 | 和大黑板時期碼表量的差不多 | ＿＿ 分鐘 |
| 放貨：發單到回報（中位數） | 員工跑一趟進貨的時間 | 同上 | ＿＿ 分鐘 |
| 超過 30 分鐘沒回報 | 忘了回報的次數（NO1 的直接指標） | 越少越好，一週內趨近 0 | ＿＿ 張 |
| 各庫有盤點的天數 | 李太太要求一天一次 | 7 / 7 | A ＿＿、B ＿＿ |
| 盤點發現數量不符 | 系統與倉庫不一致的格數（NO1 做得好，這個就會少） | 逐週下降 | ＿＿ 格 |
| 報廢籠數 | 壓壞、爛掉的量（先進先出做得好，這個就會少） | 逐月下降 | ＿＿ 籠 |

**對照組**：請李太太的兒子用手機碼表，在大黑板（或 1.0）時期量 5 次進貨、5 次出貨「從接到單到搬完」的時間，和上表的中位數比。系統的時間包含「忘了回報的時間」，所以如果中位數明顯比碼表長，代表大家還是常常晚回報，要再調整流程（例如回報按鈕放在門口的平板上）。

## 5. 還能再改（建議，未實作）

1. **掃儲位牌（最接近大黑板的手感）**：每一格貼 QR code，員工用手機掃一下 = 那一站打勾。記錄完全附著在搬貨動作上，連「勾選放好了」都省了。
2. **門口固定一台平板**：冷凍庫門口就是回報點，出門順手按，等於「把牌子掛回黑板」。
3. **完成率排行**：每週把「準時回報率」貼出來，讓回報變成習慣（李太太的兒子們也在內）。

## 6. 給老師的一句話

新系統在「找得到、先進先出、帳對得上」遠勝大黑板；它輸在「記錄要多一個動作」。2.0 不是叫員工更認真，而是**把記錄做成搬貨的一部分，並讓漏掉的一定會被看見、每天被盤點抓回來**。
