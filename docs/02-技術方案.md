## 3. 資料模型（MySQL）

對應產品方案 §2.1 的五個實體，加上兩張做「紀錄」與「復原」的表。

```
warehouse ─< slot ─< stock >─ batch >─ product
                       ▲
action ─< movement ────┘（每筆異動記「哪一格 −幾籠、哪一格 +幾籠」）
```

### 3.1 schema.sql（已實作：`db/schema.sql`，本節與該檔一致）

```sql
SET NAMES utf8mb4;

CREATE DATABASE IF NOT EXISTS zhunan CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE zhunan;

-- 冷凍庫：不寫死 A/B，之後多一座就多一列
CREATE TABLE IF NOT EXISTS warehouse (
  code         CHAR(1)     PRIMARY KEY,          -- 'A'
  name         VARCHAR(20) NOT NULL,             -- 'A 庫'
  rows_count   TINYINT     NOT NULL,             -- 幾排
  levels_count TINYINT     NOT NULL,             -- 幾層
  sort_no      TINYINT     NOT NULL DEFAULT 0    -- 畫面上的順序
);

-- 櫃位：標準化編號「庫-排-層」，貼在實體櫃位上的號碼牌就是這個 id
CREATE TABLE IF NOT EXISTS slot (
  id             VARCHAR(10) PRIMARY KEY,        -- 'A-03-2'
  warehouse_code CHAR(1)     NOT NULL,
  row_no         TINYINT     NOT NULL,
  level_no       TINYINT     NOT NULL,
  UNIQUE KEY uq_slot_position (warehouse_code, row_no, level_no),   -- 同一庫同一排同一層只會有一格
  FOREIGN KEY (warehouse_code) REFERENCES warehouse(code)
);

-- 品項：刪除是軟刪除（deleted_at 有值 = 已刪），舊批次、舊紀錄還查得到
CREATE TABLE IF NOT EXISTS product (
  id         INT          AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(20)  NOT NULL,
  shelf_days SMALLINT     NOT NULL,              -- 保存天數
  color      CHAR(7)      NOT NULL,              -- '#2e86c1'，地圖上的顏色
  deleted_at DATETIME     NULL,
  CHECK (shelf_days > 0)
);

-- 批次：FIFO 的單位。到期日預設 = 入庫日 + 保存天數，但可自訂、可事後改
CREATE TABLE IF NOT EXISTS batch (
  id          VARCHAR(20) PRIMARY KEY,           -- 'B20260921-01'（入庫日 + 當日流水號）
  product_id  INT         NOT NULL,
  in_date     DATE        NOT NULL,
  expire_date DATE        NOT NULL,
  -- FIFO 查詢「某品項依入庫日、批次編號排序」會用到這個索引
  KEY idx_batch_fifo (product_id, in_date, id),
  -- 產生新批次編號時要查「某天已經有幾批」
  KEY idx_batch_in_date (in_date),
  FOREIGN KEY (product_id) REFERENCES product(id)
);

-- 庫存堆：某批次放在某格幾籠。一批可拆放多格；一格同時只放一批（程式保證，不用 DB 約束，見技術方案 §3.3）
CREATE TABLE IF NOT EXISTS stock (
  batch_id VARCHAR(20) NOT NULL,
  slot_id  VARCHAR(10) NOT NULL,
  qty      INT         NOT NULL DEFAULT 0,       -- 出完變 0，列保留
  PRIMARY KEY (batch_id, slot_id),
  KEY idx_stock_slot (slot_id),                  -- 查「這格現在放什麼」
  CHECK (qty >= 0),                              -- 最後一道防線：程式寫錯也不會出現負庫存
  FOREIGN KEY (batch_id) REFERENCES batch(id),
  FOREIGN KEY (slot_id)  REFERENCES slot(id)
);

-- 動作：使用者按一次「確認」= 一個 action，底下可能有好幾筆 movement。復原 / 重做以 action 為單位
--   kind = normal：一般操作（可復原）
--          undo / redo：復原、重做本身（不能再被復原）
--          init：期初資料（seed 灌的假庫存，或正式上線時把大黑板搬進系統的那一次），不能被復原
CREATE TABLE IF NOT EXISTS action (
  id               INT          AUTO_INCREMENT PRIMARY KEY,
  label            VARCHAR(120) NOT NULL,        -- '入庫 甘藍菜 5 籠、毛豆 3 籠'（給復原按鈕顯示）
  kind             ENUM('normal','undo','redo','init') NOT NULL DEFAULT 'normal',
  target_action_id INT          NULL,            -- kind = undo / redo 時，指向被復原 / 重做的那個 action
  undone           TINYINT(1)   NOT NULL DEFAULT 0,
  created_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_action_undo (kind, undone, id),        -- 找「最後一個可復原 / 可重做的動作」
  FOREIGN KEY (target_action_id) REFERENCES action(id)
);

-- 異動紀錄：只增不刪。庫存變化一律表示成「from_slot −qty、to_slot +qty」，復原時反過來套就好
CREATE TABLE IF NOT EXISTS movement (
  id           INT  AUTO_INCREMENT PRIMARY KEY,
  action_id    INT  NOT NULL,
  type         ENUM('入庫','出庫','移位','盤點','改到期日','丟棄','主檔','復原','重做') NOT NULL,
  product_id   INT          NULL,
  product_name VARCHAR(20)  NULL,                -- 當時的名稱（品項改名後，舊紀錄仍顯示舊名）
  batch_id     VARCHAR(20)  NULL,
  from_slot_id VARCHAR(10)  NULL,                -- 這格 −qty
  to_slot_id   VARCHAR(10)  NULL,                -- 這格 +qty
  qty          INT          NULL,
  old_value    VARCHAR(200) NULL,                -- 改到期日 / 主檔：改之前的值（主檔存 JSON）
  new_value    VARCHAR(200) NULL,
  note         VARCHAR(200) NULL,                -- 畫面「備註」欄
  created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CHECK (qty IS NULL OR qty > 0),                -- 異動的籠數一定是正數，方向由 from / to 表示
  FOREIGN KEY (action_id)    REFERENCES action(id),
  FOREIGN KEY (product_id)   REFERENCES product(id),
  FOREIGN KEY (batch_id)     REFERENCES batch(id),
  FOREIGN KEY (from_slot_id) REFERENCES slot(id),
  FOREIGN KEY (to_slot_id)   REFERENCES slot(id)
);

-- 基本主檔：兩座庫、36 格、20 種菜（顏色與保存天數同 Demo），完整 INSERT 見 db/schema.sql
INSERT IGNORE INTO warehouse (code, name, rows_count, levels_count, sort_no) VALUES
  ('A', 'A 庫', 6, 3, 1), ('B', 'B 庫', 6, 3, 2);
-- slot 36 列：('A-01-1','A',1,1) … ('B-06-3','B',6,3)
-- product 20 列：(1,'甘藍菜',60,'#2e86c1') … (20,'番茄',45,'#d32f2f')
```

### 3.2 每種異動怎麼寫進 movement

| 使用者動作 | movement.type | from_slot | to_slot | qty | 其他欄位 |
|---|---|---|---|---|---|
| 入庫 5 籠到 A-01-2 | 入庫 | — | A-01-2 | 5 | batch_id（新建的）|
| 出庫（揀貨單一列） | 出庫 | A-03-2 | — | 3 | batch_id、note '（FIFO）' |
| 移位 A-01-2 → A-02-2 | 移位 | A-01-2 | A-02-2 | 全數 | batch_id |
| 互換 | 移位 ×2 | 各一筆 | | | note '（與 X 互換）' |
| 盤點 系統 8 → 實際 6 | 盤點 | A-01-2 | — | 2 | note '系統 8 → 實際 6' |
| 盤點 系統 8 → 實際 9 | 盤點 | — | A-01-2 | 1 | |
| 改到期日 | 改到期日 | — | — | — | batch_id、old_value、new_value |
| 丟棄整格 | 丟棄 | A-01-2 | — | 全數 | note '批次 …，超期' |
| 新增 / 編輯 / 刪除品項 | 主檔 | — | — | — | product_id、old_value / new_value（JSON） |
| 復原 / 重做 | 復原 / 重做 | — | — | — | note '復原「入庫 …」' |

規則：**庫存永遠只透過 movement 改**。程式裡只有一個函式 `applyMovement(conn, m, direction)` 會動 `stock` 表：`direction = +1` 正向套用（from −qty、to +qty），`-1` 反向套用（復原）。這樣復原永遠不會漏。

### 3.3 為什麼不做「一格只能一批」的資料庫約束

`stock` 的主鍵是 `(batch_id, slot_id)`，同一格理論上可以放兩批。Demo 和產品方案都規定一格只放一批，這由 API 檢查（入庫 / 移位前先查該格 `SUM(qty) > 0` 就拒絕）。不做 DB 約束是因為出完的舊列 qty = 0 還留著，加唯一鍵會擋到。

### 3.4 資料庫建置時補上的細節（相對於初稿）

實作 `db/schema.sql` 時補了下面幾點，其餘欄位、型別、關聯都和初稿相同：

| 補了什麼 | 為什麼 |
|---|---|
| `CREATE … IF NOT EXISTS`、主檔用 `INSERT IGNORE` | 重跑 schema.sql 不會報錯、不會清掉資料；「資料不可遺失」。要清空重來改用 `npm run db:reset` |
| 開頭 `SET NAMES utf8mb4` | 有些電腦的 mysql 指令列預設不是 UTF-8，中文主檔會變成問號 |
| `action.kind` 多一個 `'init'`（期初資料） | seed 灌的假庫存、以及正式上線時把大黑板搬進系統的那一次，都不應該被「復原」按鈕退掉 |
| `stock.qty >= 0`、`movement.qty > 0` 的 CHECK | 最後一道防線：API 寫錯也不會出現負庫存；異動方向一律由 from / to 表示 |
| `movement` 的 product / batch / slot 也加外鍵、`action.target_action_id` 加外鍵 | 紀錄不可能指到不存在的櫃位或批次 |
| `slot (warehouse_code, row_no, level_no)` 唯一 | 同一個實體位置不會有兩個編號 |
| 索引：`batch (product_id, in_date, id)`、`batch (in_date)`、`stock (slot_id)`、`action (kind, undone, id)` | 分別給 FIFO 查詢、產生批次編號、查某格放什麼、找可復原 / 重做的動作用 |
| 連線時 `SET time_zone` 成 Node 的時區（`src/db.js`） | `created_at` 記台灣時間，不是 UTC |

## 4. API 設計

- 全部走 `/api/…`，請求與回應都是 JSON。
- 成功回 `200 + 資料`；使用者的錯（籠數 ≤ 0、格子有貨、名稱重複）回 `400 { "error": "第 1 項：A-01-2 已經有貨，請換一格" }`，訊息直接給前端 toast 用。
- 每個會改資料的 API 都包在一個 MySQL 交易裡（`withTransaction`），中間任何一句失敗就整個 rollback。
- 前端每做完一個動作就重新 `GET /api/state`，不做局部更新 —— 資料只有 36 格，簡單優先。

### 4.1 讀取

| 方法 | 路徑 | 回什麼 |
|---|---|---|
| GET | `/api/state` | `{ today, warehouses, slots, products, allProducts, batches, stocks, undo: { canUndo, undoLabel, canRedo, redoLabel } }`（`today` = 伺服器的日期，前端算超期用它，不看手機時鐘；`batches`、`stocks` 只給還有貨的） —— 和 Demo 的五個陣列同名同欄位，前端的畫圖程式碼可直接用 |
| GET | `/api/movements?limit=200` | 異動紀錄，新的在前：`[{ id, time, type, productName, batchId, fromSlotId, toSlotId, qty, note, undone }]`，`undone` = 該筆所屬 action 已被復原 |

`products` 只回 `deleted_at IS NULL` 的；但 `batches` 會含已刪品項的舊批次，所以 `state` 另附 `allProducts`（含已刪）給紀錄與批次查名稱用。

### 4.2 寫入（每個對應 Demo 的一個函式）

| 方法 | 路徑 | Body | 做什麼 | Demo 對應 |
|---|---|---|---|---|
| POST | `/api/inbound` | `{ items: [{ productId, qty, slotId, expireDate }] }` | 檢查（籠數 ≥ 1、格子空、表單內不重複）→ 每項建 batch + stock + movement → 回 `{ steps: [{ slotId, productName, qty, expireDate }] }`（已依走路順序排）| `doInbound()` |
| POST | `/api/outbound/plan` | `{ items: [{ productId, qty }] }` | **不改資料**。跑 FIFO 算揀貨單，回 `{ plan: [{ slotId, batchId, inDate, productName, qty }], shortages: ['甘藍菜 差 3 籠'] }` | `makePick()` |
| POST | `/api/outbound/confirm` | `{ plan: [...]（上一步回的） }` | 再驗一次每格庫存夠 → 扣 stock、寫 movement | `confirmPick()` |
| POST | `/api/transfer` | `{ from, to }` | to 空 = 移位；to 有貨 = 互換（兩筆 movement） | `transfer()` |
| POST | `/api/adjust` | `{ slotId, qty, expireDate }` | 盤點（qty 不同）／改到期日（日期不同），可同時 | `saveModal()` |
| POST | `/api/discard` | `{ slotId }` | 整格清空 | `discard()` |
| POST | `/api/products` | `{ name, shelfDays, color }` | 新增品項；名稱重複 → 400 | `saveProdModal()` |
| PUT | `/api/products/:id` | 同上 | 編輯；movement 的 old_value / new_value 存改前改後 JSON | 同上 |
| DELETE | `/api/products/:id` | `{ confirmName }` | `confirmName` ≠ 名稱 → 400；還有庫存 → 400；否則 `deleted_at = NOW()` | `deleteProduct()` |
| POST | `/api/undo` | — | 復原最後一個未復原的 action | `undo()` |
| POST | `/api/redo` | — | 重做最後一個被復原、且之後沒有新動作的 action | `redo()` |

到期日的三種算法（依保存天數 / 指定日期 / 幾天後）在**前端**算好，送 API 時一律是 `expireDate: 'YYYY-MM-DD'`，後端不需要知道使用者選了哪種。

### 4.3 批次編號

`B{入庫日 yyyymmdd}-{當日流水 2 位}`，例如 `B20260921-03`。在交易裡找當天編號 `B{日期}-xx` 最大的 xx（`FOR UPDATE` 鎖住）再 +1。不用 `COUNT(*)`：只要有一筆舊資料的入庫日被改過，筆數就會和編號對不上而撞號。倉庫一天不會超過 99 批。

## 5. 核心邏輯

### 5.1 FIFO（老師的考點，一定要在後端、用 SQL 排序）

```sql
-- 某品項所有還有貨的庫存堆，最舊的批次排最前面；同一天入庫的依批次編號
SELECT s.batch_id, s.slot_id, s.qty, b.in_date
FROM stock s JOIN batch b ON b.id = s.batch_id
WHERE b.product_id = ? AND s.qty > 0
ORDER BY b.in_date ASC, b.id ASC;
```

`src/fifo.js` 是純函式，和 Demo 的 `fifoAllocate` 一模一樣：

```js
// candidates：上面 SQL 的結果；need：要幾籠；reserved：同一張單前面幾項已經預定的 { slotId: qty }
// 回 { plan: [{ slotId, batchId, inDate, qty }], shortage: 還差幾籠 }
function allocate(candidates, need, reserved = {}) { … 從第一筆開始扣，扣到滿足為止 … }
```

「走的順序」另外排：`plan.sort` 依 `warehouse.sort_no → row_no → level_no`。**拿哪批**（FIFO）和**怎麼走**（櫃位）是兩件事，分開寫。

### 5.2 批次狀態（超期 / 快到期）

在前端算（`app.js` 保留 Demo 的 `statusOf`），後端只給 `in_date`、`expire_date`。理由：純顯示邏輯、「20%」這個門檻之後可能想調，改一個地方就好。

### 5.3 復原 / 重做（`src/undo.js`）

- **可復原的是誰**：`kind='normal' AND undone=0` 裡 id 最大的那個 action。
- **可重做的是誰**：id 大於「最後一個有效 normal action」、且 `undone=1` 的 action 裡 **id 最小**的那個（連按兩次復原 X、Y 後，要先重做 X 再重做 Y）。復原後做了新動作就沒有可重做的，這和 Demo 的「做了新動作 redo 就清空」一致。
- **復原怎麼做**（一個交易內）：
  1. 撈該 action 的所有 movement，**由新到舊**逐筆 `applyMovement(conn, m, -1)`：
     - 有 from/to/qty 的：from 格 +qty、to 格 −qty（就是反過來）
     - 改到期日：`batch.expire_date = old_value`
     - 主檔：把 `old_value` 的 JSON 寫回 product（含 `deleted_at`）
  2. `UPDATE action SET undone=1`
  3. 新增一個 `kind='undo'` 的 action + 一筆 `type='復原'` 的 movement（note = `復原「{label}」`）
- **重做**：同上但 `direction = +1`、`undone=0`、`kind='redo'`。
- 「復原」「重做」這兩種 action 自己不能被復原；`kind='init'`（期初資料）也不能。

前端不再需要快照，`undo()` 就是 `POST /api/undo` 然後重抓 state；按鈕文字用 `state.undo.undoLabel`。

### 5.4 交易與時區（兩個新手最容易踩的坑，先寫在這）

- `src/db.js`：
  ```js
  const pool = mysql.createPool({ …, dateStrings: true, timezone: 'local' });  // 日期一律當字串 'YYYY-MM-DD'，不要讓驅動轉成 Date 物件（會差 8 小時變前一天）
  async function withTransaction(fn) { const conn = await pool.getConnection(); try { await conn.beginTransaction(); const r = await fn(conn); await conn.commit(); return r; } catch (e) { await conn.rollback(); throw e; } finally { conn.release(); } }
  ```
- `.env` 裡設 `TZ=Asia/Taipei`，伺服器算「今天」用本地日期。

## 6. 前端：Demo → public/ 的搬法

改動只有資料層，畫面程式碼不動：

| Demo 裡 | 改成 |
|---|---|
| `const products = [...]`、`slots`、`batches`、`stocks`、`movements` 與整段種子資料 | `let state = {}`；`async function reload() { state = await api.get('/api/state'); renderAll(); }` |
| `stockAt`、`batchOf`、`summarize`… 這些查詢函式 | 不動，只是從 `state.xxx` 讀 |
| `doInbound()` 裡改陣列的那段 | `const r = await api.post('/api/inbound', { items })` → 用 `r.steps` 畫路線圖 → `reload()` |
| `makePick()` 的 `fifoAllocate` | `api.post('/api/outbound/plan', …)` |
| `transfer / saveModal / discard / saveProdModal / deleteProduct` | 各自 `api.post(...)` → `reload()` |
| `commit / snapshot / restore / undo / redo` | 刪掉；`undo()` = `api.post('/api/undo')` → `reload()` |
| `toast(...)` 錯誤 | `api.js` 在 400 時 `throw new Error(json.error)`，呼叫端 `catch (e) { toast(e.message) }` |

`public/api.js`：

```js
// 十幾行：GET / POST / PUT / DELETE 都送 JSON，400 就把 error 訊息丟出去給 toast
async function request(method, url, body) { … }
const api = { get: (u) => request('GET', u), post: (u, b) => request('POST', u, b), put: …, del: … };
```

手機 / 平板：伺服器跑在辦公室電腦上，手機連同一個 Wi-Fi 開 `http://<電腦IP>:3000` 即可，不需要架站。

## 8. 啟動步驟（README 要寫的，四步）

1. 安裝 Node.js 20+ 與 MySQL 8（MySQL 記住 root 密碼）。
2. `cp .env.example .env` 填入 MySQL 密碼；`npm install`。
3. `npm run db:init`（建資料庫、表、A/B 庫、36 格、20 種菜；也可以用 `mysql -u root -p < db/schema.sql`）。
4. `npm start` → 開 `http://localhost:3000`。要 Demo 那套假庫存就多跑一次 `npm run seed`。

`package.json` scripts：`start`（`node src/server.js`）、`dev`（`node --watch src/server.js`）、`db:init`（`node db/init.js`）、`db:reset`（`node db/init.js --reset`，清空重建）、`seed`（`node db/seed.js`，資料庫已有批次就拒絕）、`test`（`node --test`）。
